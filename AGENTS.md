# Cv_Creator — agent notes

Two independent apps with no root manifest or shared tooling. Always `cd` into the app you are changing; there is no root `package.json`, Makefile, or task runner.

## Layout

- `front/` — Next.js 16 App Router UI (React 19, Tailwind v4, TypeScript, npm).
- `client/` — Python 3.12 FastAPI API using SQLModel over PostgreSQL (Neon) and OpenRouter for LLM calls.
- `client/src/` is the Python import root. Its packages (`models`, `database`, `IA_rag`, `cv_logging`, `Cv_made`) are imported as top-level modules, never `client.models` or `src.models`. New backend packages belong directly under `client/src/` with the same absolute-import style.
- `client/output/`, `client/src/Cv_made/output/`, and `client/backend_*.log` are committed artifacts. Do not regenerate or reformat them unless the task is about them.

## Frontend (`front/`)

- `cd front && npm install && npm run dev` → http://localhost:3000. Scripts: `npm run dev|build|start|lint`. There is no test runner and no Prettier; `npm run lint` is plain `eslint`, and type-checking is `npx tsc --noEmit`.
- `@/*` maps to `front/*` (not `src/`). App Router route groups are `app/(auth)` and `app/(dashboard)`; the dashboard layout is a client component that redirects to `/login` when no user is in `localStorage`.
- Auth is UI-only: the user object is kept in `localStorage` under `cv_creator_user`. There is no cookie, JWT, or server session; the backend trusts the `user_id` sent by callers.
- All HTTP calls go through `app/lib/api.ts` (`request<T>`, 60 s default timeout, 120 s for AI endpoints). New endpoints need matching types in `app/lib/types.ts`.
- Backend CORS only allows `http://localhost:3000`. If Next falls back to port 3001, API calls fail with CORS errors.
- Next 16 has breaking changes versus older Next knowledge. `front/AGENTS.md` is generated by `next dev` and tells you to read `node_modules/next/dist/docs/` before writing Next code — install dependencies first, and keep that block in the tree. `front/CLAUDE.md` simply imports it.

## Backend (`client/`)

- Start the API from `client/`: `uv run uvicorn client:app --app-dir src --reload` (or the `uv run client` entrypoint, without reload). The FastAPI app and router wiring live in `client/src/client/__init__.py`; routers are in `client/src/client/router/`.
- Run from `client/` so `dotenv` finds `client/.env`. Required env vars: `DATABASE_URL` (Postgres/Neon, SSL required by the engine), `OPENROUTER_API`, `MODELO` (OpenRouter model id). `MODELO_ANALISIS` optionally overrides the model used for CV analysis. `MODO_ECONOMICO=1` skips the LLM-written summary entirely: the four metrics and the improvement list are deterministic, so the analysis works with no AI quota (OpenRouter free tier is 50 requests/day per account, shared by all `:free` models). Free OpenRouter ids (`...:free`) work; the analysis narrative already grants 4000 tokens because reasoning models otherwise answer with empty content.
- There are no migrations. `create_all_tables()` runs on FastAPI startup and only creates missing tables; it does not alter existing ones, so column or type changes you make to models will not reach an existing database.
- Logging writes to the cwd-relative path `client/logs` (`cv_logging/logger.py`, `log_routes.py`). Started from `client/`, files actually land in `client/client/logs`; keep the working directory consistent when debugging logs.
- `client/src/IA_rag/SPEC.md` is an outdated draft design doc (it references `openrouter.py`, which is now `generator.py`). Trust the code over that spec.
- `client/src/Cv_made/` (Harvard DOCX/PDF renderers, ATS validation, Prefect flow) is imported by the API for `/api/cv/export` and `/api/cv/ats-report`. Its `__init__.py` stays light on purpose: it must not pull Prefect, which is only used by `flow_Create.py`.
- Backend tests live in `client/tests/` (pytest): metrics/keywords, Harvard renderers, ATS validation and the export routes. They need no DB and no LLM credentials. Run them from `client/` with `uv run pytest`. No Ruff, mypy, pre-commit, or CI is configured.

## Verify

- Frontend: `cd front && npm run lint && npx tsc --noEmit` (add `npm run build` for route/type issues).
- Backend tests: `cd client && uv run pytest`.
- Backend routes: start the API and exercise the changed route through FastAPI's `/docs` or a `curl` call. Do not claim a backend change works without a live request.
